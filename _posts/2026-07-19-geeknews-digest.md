### 1. 「Machine Learning Study 혼자 해보기」 (79pts)

**[원문 바로가기](https://github.com/teddylee777/machine-learning)**

**요약**: 이 저장소는 머신러닝과 딥러닝을 독학하거나 스터디를 꾸리려는 학습자를 위해 강의, 블로그, 논문, 데이터셋과 튜토리얼을 한국어 중심으로 큐레이션한다. 파이썬·판다스·넘파이·시각화에서 수학·통계, 전통 머신러닝, 딥러닝, 강화학습과 생성형 인공지능으로 이어지는 탐색 경로를 제공한다. 작성자가 직접 수강한 자료에는 평가와 추천 순서를 붙여 단순 링크 모음보다 선택 비용을 낮췄다. 여러 프레임워크와 공개 자료를 한곳에서 비교할 수 있지만, 외부 링크와 버전 변화가 많아 최신성 점검은 학습자가 맡아야 한다. 장기간 축적된 커밋과 포크는 일회성 목록이 아니라 한국어 학습 커뮤니티의 실용적 출발점으로 쓰였음을 보여준다.

**기술적 배경**: 생성형 인공지능이 코드를 즉시 만들더라도 데이터 누수, 과적합, 평가 설계와 통계적 추론은 자동 완성만으로 대체되지 않는다. 단일 유료 강좌나 한 프레임워크에 잠그지 않고 기초→실습→논문·프로젝트로 이어지는 공개 경로를 제시하는 것이 차별점이며, 서울대 평생교육원 과정의 참고 링크로도 사용됐다.

**영향 분석**: 개발자는 필요한 개념을 빠르게 복습하고 공식 문서로 이동할 수 있고, 스타트업은 주니어 온보딩 자료를 만드는 시간을 줄일 수 있다. 인디 빌더는 제품 가설과 직접 연결된 5~10개 자료만 골라 실험으로 닫아야 ‘자료 수집이 학습’이 되는 함정을 피할 수 있다.

**Master 액션 포인트**:

1. OpenClaw 위키 인덱서로 링크 상태와 갱신일을 검사해 게임·카메라 앱에 필요한 컴퓨터 비전, 추천, 시계열 자료만 실행형 학습 경로로 축약한다.
2. 각 경로의 완료 조건을 `노트북 실행 → 작은 데이터셋 평가 → 제품 적용 여부 기록`으로 고정해 eastsea.xyz 실습 글로 자산화한다.

### 2. Mindwalk — 코딩 에이전트 세션을 코드베이스의 3D 지도에서 재생 (1pts)

**[원문 바로가기](https://github.com/cosmtrek/mindwalk)**

**요약**: Mindwalk는 Claude Code와 Codex의 세션 로그를 읽어 저장소 지도 위에서 검색·읽기·편집·검증 흐름을 빛의 이동으로 재생하는 로컬 도구다. 트리와 지형 보기에서 파일별 접근 깊이, 오류율, 반복 수정, 마지막 검증 뒤 편집 같은 신호를 한눈에 보여준다. 타임라인에는 컨텍스트 압축, 사용자 턴, 서브에이전트 실행이 표시되고 각 에이전트의 흔적을 따로 재생할 수도 있다. 기본 열람은 로컬 Go 서버에서 끝나며, 명시적으로 평가를 실행할 때만 작업 문구·파일 경로·이벤트 요약이 사용자의 Claude 또는 Codex CLI 모델로 전송된다. 세션 추적, 결정론적 저장소 지도, 선택적 모델 평가를 분리해 같은 코드베이스의 여러 작업을 비교 가능하게 만든 설계가 핵심이다.

**기술적 배경**: 원시 JSONL은 도구 호출 순서를 보여주지만 에이전트가 어떤 영역을 중요하게 봤고 실제 수정 범위가 요청과 맞았는지는 빠르게 드러내지 못한다. 기존 로그 뷰어와 달리 범위 이탈·탐색 편향·검증 공백을 공간적 패턴으로 표현하지만, 3D 재생이 텍스트 요약보다 항상 빠르다는 독립 검증은 아직 없다.

**영향 분석**: 개발자는 실패 세션의 ‘어디서 헤맸는지’를 리뷰하고 좋은 탐색 패턴을 재사용할 수 있다. 스타트업과 인디 빌더는 다중 에이전트 작업의 감사 가능성을 높일 수 있지만, 시각화 자체를 품질 판정으로 착각하지 말고 테스트·차이 검토와 함께 써야 한다.

**Master 액션 포인트**:

1. OpenClaw 세션 10개를 Mindwalk로 재생해 범위 이탈, 반복 수정, 검증 뒤 재편집 비율을 기준선으로 기록한다.
2. 평가 기능은 비밀 경로가 없는 익명화 세션에서만 시험하고, 평소 열람은 완전 로컬 모드로 제한한다.

### 3. StackRender — 데이터베이스 스키마 설계·생성 도구 (11pts)

**[원문 바로가기](https://github.com/stackrender/stackrender)**

**요약**: StackRender는 텍스트 사양이나 기존 SQL에서 시각적 ERD를 만들고 다시 SQL DDL로 내보내는 공개 베타 도구다. 드래그앤드롭 편집, 테이블·열·제약조건 관리, 인덱스 제안, 외래키 순환 탐지를 제공한다. PostgreSQL, MySQL, MariaDB, SQLite, Oracle과 SQL Server 스키마를 지원하며 Docker로 자체 호스팅할 수 있다. 클라우드판은 자연어 사양에서 스키마 생성, 소프트 삭제 필드 추가, 문서화와 스키마 보강 같은 인공지능 기능을 덧붙인다. 최근 문서는 ERD 변경을 추적해 상향·하향 마이그레이션을 생성하는 흐름까지 강조하지만, 공개 베타이므로 실제 운영 데이터베이스에 적용하기 전 생성 SQL 검토와 복구 시험이 필요하다.

**기술적 배경**: ORM 마이그레이션은 코드 중심이고 전통 ERD 도구는 설계 그림과 실제 변경 이력이 쉽게 분리된다. StackRender의 차별점은 시각적 설계, 스키마 차이, 다중 SQL 방언과 마이그레이션을 한 흐름에 묶는 것이며, AGPLv3 라이선스는 네트워크 서비스로 수정 배포할 때 소스 공개 의무를 검토하게 한다.

**영향 분석**: 개발자와 작은 팀은 백엔드 초기 설계와 리뷰 시간을 줄일 수 있지만, 인공지능이 제안한 인덱스나 제약조건은 실제 쿼리 부하를 모르면 오히려 성능을 해칠 수 있다. 인디 빌더에게는 프로토타입 스키마를 빠르게 만들고 diff를 남기는 도구로 유용하되 프로덕션 적용은 기존 마이그레이션 도구가 최종 권위여야 한다.

**Master 액션 포인트**:

1. 게임 백엔드 한 개의 읽기 전용 스키마를 가져와 생성 DDL과 기존 마이그레이션의 차이를 비교하는 샌드박스 평가를 한다.
2. 도입한다면 `생성 SQL 정적검사 → 빈 데이터베이스 적용 → 롤백 → 데이터 보존 검증`을 필수 게이트로 묶는다.

→ 교차확인: [SourceForge의 StackRender 프로젝트 설명](https://sourceforge.net/projects/stackrender/)

### 4. 소비자 앱을 구축하고 확장하는 법 (29pts)

**[원문 바로가기](https://x.com/jakecastilloooo/status/2069417525947912540)**

**요약**: Cal AI 공동창업자 제이크 카스티요는 소비자 앱 성장의 가장 큰 병목이 제품 개발보다 유통이라고 주장한다. 소수 팀이 1만 명이 넘는 크리에이터 후보를 검토하고, 팔로워 수보다 평상시 조회수·댓글의 대화 품질·시청자의 친밀감을 빠르게 평가했다. 제품과 표면적으로 어울리는 채널보다 실제 구매 동기가 맞는 틈새를 3~5회 반복 시험한 뒤 성과가 없으면 중단했다. 크리에이터에게는 제품 설명과 금지사항만 짧게 전달하고 제작 방식은 맡겼으며, 계약·알림·성과 기록·재계약을 자동화했다. 기능과 디자인이 빠르게 복제되는 시장에서 방어력은 단일 바이럴이 아니라 반복 가능한 선별·실험·중단 시스템이라는 결론이다.

**기술적 배경**: 전통 광고는 소재와 노출을 중앙 통제하지만 크리에이터 유통은 이미 형성된 신뢰와 채널 고유의 표현을 산다. Business Insider는 Cal AI가 작은 창업팀과 인플루언서 중심 전략으로 성장해 MyFitnessPal에 인수된 배경을 확인했지만, 특정 수치와 전술의 인과관계는 회사 사례에서 일반화하면 안 된다.

**영향 분석**: 인디 앱과 게임은 완성 뒤 마케팅을 시작하지 말고 개발과 동시에 장르별 크리에이터 적합성을 실험해야 한다. 스타트업은 팔로워 수나 조회수 하나보다 설치·유지율·재계약률을 연결해야 유통 학습이 자산으로 남는다.

1. 다음 게임 출시에서 `20초 선별 → 장르별 3~5회 테스트 → 성과 없는 틈새 중단` 흐름을 자동화한다.

### 5. LeafWiki — 서버와 DB 없이 단일 바이너리로 실행하는 셀프 호스팅 위키 (13pts)

**[원문 바로가기](https://leafwiki.com/)**

**요약**: LeafWiki는 페이지 본문을 디스크의 Markdown 파일로 두고 단일 Go 바이너리와 경량 SQLite 메타데이터로 실행하는 셀프 호스팅 위키다. 폴더 트리, 전체 검색, 태그 필터, 위키 링크, 백링크와 깨진 링크 표시를 제공한다. 페이지 이동 시 링크를 갱신하고 선택적 수정 이력, Mermaid, KaTeX, 이미지 붙여넣기를 지원한다. Linux·macOS·Windows·Raspberry Pi에서 동작하며 개인 위키, 런북, 홈랩 문서와 작은 팀 노트를 주 대상으로 삼는다. 실시간 공동 편집, 복잡한 권한·승인 흐름, 올인원 협업 기능을 의도적으로 제외해 운영 부담과 잠금을 줄이는 것이 제품 철학이다.

**기술적 배경**: Notion·Confluence·Outline 같은 대안은 협업 기능이 강하지만 데이터베이스와 서비스 스택, 전용 내보내기 형식이 따라온다. LeafWiki는 평문 파일을 기준 데이터로 유지해 `cp -r` 백업과 외부 편집이 가능하다는 점이 다르지만, 메타데이터·권한과 실시간 협업이 필요한 조직에는 맞지 않는다.

**영향 분석**: 작은 개발팀은 문서 시스템 자체를 운영하는 비용을 줄이고 파일 기반 에이전트 워크플로와 쉽게 연결할 수 있다. OpenClaw에는 현재 Markdown 위키 철학과 잘 맞지만, 기존 RAG·링크 인덱스와 기능이 겹치므로 교체보다 읽기 전용 시험이 안전하다.

**Master 액션 포인트**:

1. `memory/` 복제본을 LeafWiki 읽기 전용 인스턴스에 마운트해 검색·백링크·링크 리팩터링의 실효성을 비교한다.
2. 편집 권위는 Git과 현재 위키 파이프라인에 남기고, 자동 링크 수정은 별도 브랜치와 차이 검토를 통과하게 한다.
