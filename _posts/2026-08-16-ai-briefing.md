## Executive Summary
- **월드 모델이 오늘의 주제다.** Hugging Face 데일리 페이퍼 상위권이 인터랙티브 월드 모델(Alaya-EVOKE 82업보트)·장기 과제 월드 모델 벤치마크(PlayWorld)·로봇 조작 월드 모델로 채워졌다. "생성 품질"에서 "끊기지 않는 상태 유지"로 문제 정의가 옮겨가는 흐름이 뚜렷하다.
- **하네스 진화가 자동화된다.** Salesforce DarwinX는 프롬프트·도구·스킬·제어 흐름을 '개체군 자연선택'으로 진화시키는 프레임을 제시했고, HKUDS CLI-Anything은 모든 소프트웨어를 에이전트가 쓸 수 있는 CLI로 바꾸는 허브를 열었다. 에이전트 인프라 경쟁이 모델 경쟁을 압도하는 국면이다.
- **일본 생태계가 인프라 규모로 반격 중이다.** Microsoft의 1.6조엔(100억 달러) 일본 투자가 개발자 커뮤니티에서 "일본은 AI 후진국" 프레임 반박 재료로 재조명되고, Qiita에서는 코딩 에이전트 실무 비교·에이전트 재시행 설계 같은 깊이 있는 실전 글이 쏟아진다.

## 🔬 논문 동향

**1. Alaya-EVOKE — 선형 스케일 감독으로 끝없는 월드 모델 만들기** (arXiv / Hugging Face 데일리 페이퍼)
- **사실:** 인터랙티브 월드 모델의 치명약점인 "세션이 길어질수록 맥락 유지 비용이 폭증"하는 문제를, 영구 상태를 외부 월드 스테이트 뱅크(카메라 인덱스 방식)로 내보내고 뷰 관련 정보만 검색하는 구조로 해결한 논문이다. 교사 모델은 청크 그룹화·원거리 프레임 검색·선형 어텐션 전역 상태를 결합해 메모리·연산이 선형 증가에 그친다.
- **수치:** 30초 분포 정합 목표를 자기 강제 롤아웃 하에 적용해, **3스텝만에 생성하는 학생 모델**(CFG 불필요)로 능력을 전이했다. 8월 15일 HF 데일리 페이퍼 **업보트 82**로 당일 최상위권이다.
- **시사점:** 게임·시뮬레이션 같은 장기 인터랙션 생성의 병목이 "모델 용량"에서 "상태 관리 설계"로 이동했다. 지속 세계를 다루는 인디 게임 AI 파이프라인 설계에 바로 참고할 구조다.
→ 원문: [Alaya-EVOKE: From Linear-Scaling Supervision to Endless World](https://arxiv.org/abs/2608.13546)
→ 교차확인: [Hugging Face Daily Papers (Alaya-EVOKE)](https://huggingface.co/papers/2608.13546)

**2. DarwinX — 에이전트 하네스를 자연선택으로 진화시키기** (Salesforce AI Research / arXiv)
- **사실:** LLM 에이전트 능력이 모델 가중치만이 아니라 프롬프트·도구·스킬·제어 흐름(하네스)에 달려 있다는 관점에서, 모델을 동결한 채 **하네스 개체군에 자연선택을 적용**하는 DarwinX를 제안했다. 핵심 장치는 '보존-확장 계약'(다른 과제 회귀 없이 커버리지만 늘리는 변이만 채택)과 대안 혈통을 보관해 재조합하는 아카이브다.
- **수치:** 실패·교사·자기 유도 증거가 하나의 편집 인터페이스로 통합되며, 단일 혈통 탐색의 경로 의존성(지역 최적 함정)을 구조적으로 회피한다. HF 데일리 페이퍼 **업보트 58**.
- **시사점:** OpenClaw 스킬·브리핑 파이프라인처럼 "하네스를 매일 손으로 고치는" 운영에 그대로 대입되는 프레임이다. 스킬 워크숍에 회귀 방지 계약과 혈통 아카이브 개념을 이식하면 자기개선 루프가 안정화된다.
→ 원문: [DarwinX: Evolving Agent Harnesses Through Natural Selection](https://arxiv.org/abs/2608.07545)
→ 교차확인: [Hugging Face Daily Papers (DarwinX)](https://huggingface.co/papers/2608.07545)

**3. Intern-S2-Preview — 과학용 에이전틱 파운데이션 모델 프리뷰** (상하이 AI Lab Intern / arXiv)
- **사실:** InternLM 계열이 '과학 에이전트 파운데이션 모델' 프리뷰 논문을 공개했다. 제목과 게재 형태가 뜻하듯 과학 워크플로 전반을 수행하는 에이전틱 기반 모델의 사전 공개 성격이며, 상세 벤치마크는 본문 확인이 필요하다.
- **수치:** HF 데일리 페이퍼 **업보트 42**로 논문 랭킹 중위권 상단. 같은 날 OmniScientist(옴니모달 AI 과학자) 같은 유사 주제 논문도 함께 올라왔다.
- **시사점:** "AI 과학자"가 감상용 데모에서 파운데이션 모델 경쟁으로 편입되는 신호다. 도메인 특화 에이전트 모델 시장이 코딩 다음 과학으로 확장되는 흐름을 따라갈 만하다.
→ 원문: [Intern-S2-Preview: Scientific Agentic Foundation Model](https://arxiv.org/abs/2608.13505)

**4. PlayWorld — 에이전트 플레이어로 월드 모델을 벤치마킹하기** (홍콩대 / arXiv)
- **사실:** 월드 모델의 품질을 짧은 클립 생성 품질이 아니라, **에이전트가 장기 목표를 수행하는 과정**에서 평가하는 벤치마크 논문이다. 월드 모델과 에이전트 학습을 하나의 루프로 묶는 최근 흐름의 평가 인프라에 해당한다.
- **수치:** HF 데일리 페이퍼 **업보트 33**. 같은 주에 로봇 조작용 영상 월드 모델(DreamX-Phi, 업보트 79)도 상위권에 올라 월드 모델 축이 벤치마크·로보틱스·인터랙티브로 3방향 확산 중임을 보여준다.
- **시사점:** 게임 AI에 월드 모델을 쓰려면 "긴 호라이즌에서 붕괴하지 않는가"가 진짜 평가 기준이다. 이 벤치마크 계열이 게임 시뮬레이션 평가의 표준 후보로 자리 잡을 가능성을 주시하자.
→ 원문: [PlayWorld: Benchmarking World Models with Agent Players over Long-Horizon Objectives](https://arxiv.org/abs/2608.13552)

## 🤖 모델/도구 릴리즈

**5. Kimi K3 '무료' 소문 검증 — 무료 체험과 조건의 경계** (Qiita / Moonshot)
- **사실:** "Kimi K3가 무료라던데?"라는 소문을 직접 뒤져보니 상당 부분 오해였다고 정리한 Qiita 글이 8월 16일 올라왔다. 무료라는 인식과 실제 이용 조건 사이의 간극을 구체적 확인 없이 그대로 믿으면 안 된다는 결론이다.
- **수치:** Kimi K3는 이미 unsloth가 로컬 학습·실행 대상 공식 목록(Qwen3.8, MiniMax-H3, Gemma 4, DeepSeek-V4와 나란히)에 포함될 만큼 로컬 생태계 표준 대열에 올라 있다.
- **시사점:** 프론티어급 중국 모델의 '무료' 프레임은 마케팅 후크인 경우가 많다. 도입 전 원문 요금제·API 조건을 항상 1차 확인하는 습관이 실수를 막는다.
→ 원문: ["Kimi K3、無料らしいよ"と思って調べたら、けっこう勘違いしていた話](https://qiita.com/mamagotolab/items/a5cd77a69f344651ea47)
→ 교차확인: [unslothai/unsloth (Kimi K3 지원 명시)](https://github.com/unslothai/unsloth)

**6. Soup — YAML 하나로 LLM 파인튜닝, 4GB 노트북 GPU에서 8B 학습** (GitHub)
- **사실:** 파인튜닝 전체를 단일 YAML로 정의하고, 레이어 스트리밍으로 **4GB 노트북 GPU에서 8B 모델 학습**을 가능하게 한 도구가 Python 트렌딩에 진입했다. 실험 구성의 코드화(선언형)로 재현성 문제를 구조적으로 줄이는 접근이다.
- **수치:** 8월 16일 기준 **스타 1,688개, 하루 +297개**로 급등 중. 빌트 바이 목록에 claude가 등록돼 있어 AI 협업 개발 산물로도 눈길을 끈다.
- **시사점:** 개인 GPU(또는 5080 16GB 원격 머신)로 소형 모델 특화 파인튜닝을 하려는 워크플로우의 진입장벽이 사실상 'YAML 작성'으로 낮아졌다. Jay의 게임 데이터 기반 특화 모델 실험 후보로 바로 둘 만하다.
→ 원문: [MakazhanAlpamys/Soup (GitHub)](https://github.com/MakazhanAlpamys/Soup)

**7. SGLang-Omni — 음성·옴니모델 고성능 서빙 스택** (SGLang / GitHub)
- **사실:** SGLang 팀이 TTS·ASR·음성 및 옴니(멀티모달 실시간) 모델을 위한 고성능 서빙 프로젝트를 공개했다. 텍스트 LLM 서빙에서 검증된 SGLang의 스케줄링 노하우를 실시간 음성 파이프라인으로 확장하는 것이 골자다.
- **수치:** 공개 초기임에도 **스타 820개·포크 341개**로 순항 중. 컨트리뷰터에 SGLang 창시자진이 직접 붙어 있다.
- **시사점:** 실시간 음성 에이전트 제품(게임 내 보이스, 고객지원)의 셀프호스팅 비용 구조를 바꿀 잠재력이 있다. 음성 인터랙션 기획 시 API 의존 탈출 경로로 기억해두자.
→ 원문: [sgl-project/sglang-omni (GitHub)](https://github.com/sgl-project/sglang-omni)

## 👨💻 개발자 생태계 (GitHub/커뮤니티)

**8. CLI-Anything — 모든 소프트웨어를 에이전트-네이티브로** (HKUDS / GitHub)
- **사실:** LightRAG 등을 낸 HKUDS가 "모든 소프트웨어를 에이전트가 호출 가능한 CLI로 만든다"는 CLI-Anything과 CLI-Hub(clianything.cc)를 공개했다. MCP·함수 호출로 하나씩 붙이던 도구 연동을 CLI 표준으로 일괄 해제하겠다는 전략이다.
- **수치:** 공개 직후 GitHub Python 데일리 트렌딩 상위권에 진입했다. 존재하지 않는 CLI를 갖고 있는 레거시 도구까지 에이전트 자산으로 바꾸는 범용성이 차별점이다.
- **시사점:** Jay의 게임 제작·배포 도구 체인(make 스크립트, itch.io butler 등)은 이미 CLI 체계라 에이전트 연동비용이 낮다. 이 허브에 등록해두면 검색·발견 경로가 생긴다.
→ 원문: [HKUDS/CLI-Anything (GitHub)](https://github.com/HKUDS/CLI-Anything)
→ 교차확인: [CLI-Hub (clianything.cc)](https://clianything.cc/)

**9. SPORK — 툴 결과를 기다리는 동안 추론 공백을 메우는 선제 호출** (Qiita)
- **사실:** 에이전트가 도구 호출 결과를 대기하는 동안 추론 파이프라인이 놀게 되는 문제를, 다음에 필요할 호출을 미리 시작해 공백을 메우는 기법을 정리한 Qiita 글이다. 지연 시간 최적화 관점에서 에이전트 런타임 설계를 다룬다.
- **수치:** '추론 중 호출 선독(先讀)'이라는 표현 그대로, 툴 대기·추론을 병렬로 겹치는 스페큘레이티브 실행 계열 패턴의 일본 커뮤니티 확산 사례다.
- **시사점:** 초당 수백 토큰 시대에 남는 병목은 모델이 아니라 워크플로우 직렬 대기다. 브리핑 크론 같은 다중 fetch 파이프라인에 동일 원리(선제 페치)를 적용하면 총 소요시간을 눈에 띄게 줄일 수 있다.
→ 원문: [ツール結果を待つ間の空転を埋めるSPORK、推論中に呼び出しを先読み (Qiita)](https://qiita.com/okssusucha/items/321686139b4d5ec3a591)

**10. 에이전트 재시행 설계 — 재시도·재개·재승인을 분리하라** (Qiita)
- **사실:** AI 에이전트의 재시도를 전부 동일하게 취급하지 말고, 책임 경로를 나눠 **재시도(동일 작업 반복)·재개(중단 지점부터)·재승인(사람 개입)** 을 구분 설계하자는 실전 글이 올라왔다. 자동 재시도가 부작용(중복 발송, 비용 폭증)으로 이어지는 사례를 다룬다.
- **수치:** 같은 날 Qiita AI 태그 상위 노출권. 8월 15일자 브리핑이 다룬 '책임 경로 OS' 관점과 정확히 같은 축의 일본 발 실무 담론이다.
- **시사점:** OpenClaw 크론·스폰 파이프라인의 재시행 정책도 이 3분법으로 점검할 가치가 크다. 특히 외부 발신(디스코드, D1 퍼블리시)이 포함된 작업은 재승인 경로가 기본이어야 한다.
→ 원문: [AIエージェントの再試行を全部同じにしない――責任経路OSで再試行・再開・再承認を分ける (Qiita)](https://qiita.com/dantarg/items/0cae486e3c330fcc89e3)

**11. 코딩 에이전트 5종 실무 비교 2026년 8월판 + OpenClaw 연계** (Qiita)
- **사실:** Claude Code·GitHub Copilot·Cursor·Windsurf·Codeium을 구현 관점에서 비교한 8월판 정기 시리즈가 나왔고, 같은 저자가 OpenClaw×Claude Code로 '사고와 실행을 분업하는' 개발 플로우 실전 글도 함께 발행했다.
- **수치:** 시리즈가 '월간 갱신'으로 운영될 만큼 코딩 에이전트 시장의 변화 속도가 월 단위임을 보여준다. 도구 선택이 벤치마크가 아니라 실사용 로그 기준으로 재평가되는 흐름과 맞닿아 있다.
- **시사점:** 하네스(에이전트 런타임)와 모델을 분리해 조합하는 구조가 일본 실무 현장에서도 표준화되고 있다. Jay의 스킬 자산화 전략을 도구 종속 없이 유지하는 방향과 일치한다.
→ 원문: [【2026年8月版】Claude Code・GitHub Copilot・Cursor・Windsurf・Codeiumを実装目線で比較する (Qiita)](https://qiita.com/sescore/items/216e6f75dff95bf1c661)

## 미스 김 인사이트 💋

### 오늘의 핵심 트렌드 3가지
1. **월드 모델의 문제 정의가 '길이'로 바뀌었다.** 짧은 클립 품질 경쟁(Alaya-EVOKE의 외부 상태 뱅크, PlayWorld의 장기 벤치마크)이 증명하듯 승부처는 세션이 길어져도 붕괴하지 않는 상태 관리 설계다.
2. **에이전트 개선의 단위가 모델에서 하네스로 확정됐다.** DarwinX(하네스 자연선택)와 CLI-Anything(전 소프트웨어 CLI화)이 같은 나을 가리킨다. 스킬·도구·제어 흐름의 자산화가 곧 경쟁력이다.
3. **실행 지연 최적화 담론이 커뮤니티로 확산 중이다.** SPORK류의 선제 호출 패턴이 일본 개발자 문서화 단계에 들어섰다. 이제 속도 경쟁은 API 응답속도가 아니라 워크플로우 직렬 대기 제거에서 벌어진다.

### Jay에게 추천
- **즉시 실행:** Soup로 poc-cuda(5080 16GB)에서 8B급 게임 특화 파인튜닝 스모크 테스트. YAML 선언형이라 실험 재현 비용이 거의 0이고, 브리핑·게임 카피 생성 로컬라이즈에 바로 써먹을 수 있다.
- **주목:** DarwinX의 '보존-확장 계약'을 스킬 워크숍 개선 루프에 이식. 기존 스킬 회귀 없이 새 변이만 수용하는 게이트가 없으면 자기개선은 결국 퇴행한다.
- **관망:** Kimi K3 '무료' 이야기는 요금제 원문 확인 전까지 미신으로 취급. 무료 체험 조건이 언제 바뀌는지 추이만 지켜본다.

### 다음 1주 전망
월드 모델 3방향 확산(벤치마크·로보틱스·인터랙티브)이 게임 엔진 통합 사례로 이어질 관측 지점이다. 또한 에이전트 하네스 진화 연구(Salesforce 계열)가 오픈소스 구현을 동반해 터질 가능성이 높으니, CLI-Anything 허브와 함께 하네스 실험 인프라를 미리 깔아두는 쪽이 유리하다. 일본 인프라 투자 재조명은 국내외 클라우드 비용 인하 뉴스로 이어질 변수다.
