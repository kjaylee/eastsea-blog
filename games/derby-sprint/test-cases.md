# Derby Sprint Test Cases

| ID | 영역 | 절차 | 기대 결과 |
|---|---|---|---|
| TC-01 | 타이틀 | 기본 주소를 연다 | 제목, 최고 기록 4종(BEST SCORE/TIME/WINS/RUNS), `출전표 보기` 버튼이 보인다 |
| TC-02 | 출전표 | 타이틀에서 시작한다 | 랜덤 날씨 배너(이름·계절·헤드라인·연구 근거 노트)와 말 카드 3장이 표시된다 |
| TC-03 | 날씨 랜덤 | 출전표를 여러 번 다시 연다 | 4종 날씨(쾌설/폭염/강우/한파)가 레이스마다 다르게 등장한다 |
| TC-04 | 말 카드 | 카드 3장을 순서대로 누른다 | 선택 테두리가 이동하고 4개 스탯 바(가속/속도/지구력/스퍼트)가 체형별로 다르다 |
| TC-05 | 날씨 적성 배지 | 폭염/강우/한파에서 출전표를 확인한다 | 스프린터=취약/위험/우세, 스테이어=우세/우세/불리 배지가 맞게 표시된다 |
| TC-06 | 레이스 시작 | `1400m 레이스 시작`을 누른다 | 6레인 트랙, HUD(날씨/잔여거리/순위/속도), 스태미나 바가 나타난다 |
| TC-07 | 가속 | 화면(또는 Space)을 누르고 있는다 | 속도가 상승하고 스태미나가 감소하며 말 다리가 빠르게 움직인다 |
| TC-08 | 회복 | 놓는다 | 크루징 속도로 안정되고 스태미나가 천천히 회복된다(완회복 아님) |
| TC-09 | 지진 현상 | 스태미나를 0까지 소모한다 | `지진 현상` 플래시와 함께 급감속(5m/s 수렴)하고 일정 회복 후 재가속이 가능해진다 |
| TC-10 | 한파 초반 봉인 | 한파 레이스 초반 200m를 누른다 | 가속이 봉인되어 평소보다 느리게 붙어나가고 스프린터가 상대적으로 덜 감소한다 |
| TC-11 | 폭염 소모 | 폭염에서 같은 페이싱을 반복한다 | 스태미나 감소가 쾌설 대비 +20%(스프린터는 추가 ×1.30) 증가한다 |
| TC-12 | 강우 접지력 | 강우에서 스퍼트 존에 진입한다 | 스프린터는 스퍼트 효율이 크게 떨어지고 스테이어는 유지된다 |
| TC-13 | 스퍼트 존 | 1000m 지점을 통과한다 | `스퍼트 존 돌입` 토스트, 골드 밴드 표시, 잔여 스태미나 비례 배수 가속이 작동한다 |
| TC-14 | AI 스타일 | 레이스를 관전한다 | 선행마는 초반 선두 후 부화, 추입마는 후반 급가속하는 3종 페이싱이 보인다 |
| TC-15 | 완주 | 결승선을 통과한다 | 나머지 말의 착순까지 확정되고 결과 화면(착순표·착차·기록)이 열린다 |
| TC-16 | 결과 상세 | 결과 화면을 확인한다 | 잔여 스태미나 %, 날씨×체형 적성, 적성 보너스(+250/+100/0), 점수가 표시된다 |
| TC-17 | localStorage | 1회 완주 후 새로고침한다 | 최고 점수·최단 우승 기록·승수·주행 수가 복원된다 |
| TC-18 | 재도전 | `REBUILD & RACE`를 누른다 | 새 날씨가 뽑힌 출전표로 돌아간다 |
| TC-19 | 모바일 | 390×844 뷰포트에서 실행한다 | 가로 스크롤/확대 없이 HUD·6레인·스태미나 바가 안전영역 내에 있다 |
| TC-20 | 키보드 | Space를 누르고 놓는다 | 터치와 동일하게 가속·회복이 동작한다 |
| TC-21 | QA 자동화 | `?qa=1`로 열고 1초 대기한다 | `window.__qaResult.pass === true` (12 어설션), `pageErrors=[]` |
| TC-22 | 텍스트 건전성 | `render_game_to_text()`를 검사한다 | `undefined`, `NaN` 문자열이 0개다 |
| TC-23 | 재생 제어 | `window.advanceTime(ms)`와 `window.__derbySprint` 훅을 호출한다 | 결정론적으로 상태가 전진하며 자동 검증이 가능하다 |
| TC-24 | 정적 검증 | 추출한 JS를 `node --check` 한다 | 구문 오류 0개, 헤더 주석에 연구 원천 인용 존재 |
