# Piston Pocket Derby Test Cases

| ID | 영역 | 절차 | 기대 결과 |
|---|---|---|---|
| TC-01 | 타이틀 | 기본 주소를 연다 | 제목, 오늘 트랙, 최고 기록, `ENTER WORKSHOP`이 보이고 게임은 정지 상태다 |
| TC-02 | 시작 | 시작 버튼을 누른다 | 오버레이가 닫히고 `mode=play`, 거리와 두 피스톤 게이지가 표시된다 |
| TC-03 | 독립 멀티포인터 | 왼쪽과 오른쪽 반쪽에 서로 다른 pointerId로 누른다 | 두 포인터가 각각 `left/right`에 매핑되고 두 압축값이 독립 증가한다 |
| TC-04 | 비대칭 해제 | 왼쪽만 50% 이상 압축 후 놓는다 | 수직 반발과 함께 차체 각속도가 코를 올리는 방향으로 변한다 |
| TC-05 | 동시 해제 | 좌우를 50% 이상 압축한 뒤 140ms 이내에 모두 놓는다 | `twinLaunches`가 증가하고 단일 해제보다 큰 수직 점프가 발생한다 |
| TC-06 | 키보드 대체 | `A/←`, `D/→`를 누르고 놓는다 | 각 키가 해당 피스톤의 압축·해제와 동일하게 동작한다 |
| TC-07 | Camshaft | 35% 이후까지 주행한다 | 더 큰 굴곡/톱니 지형과 경고 표지, 왕복 프레스 게이트가 등장한다 |
| TC-08 | Draft | 첫 체크포인트에 도달해 `Soft Coil`을 고른다 | 초안 오버레이가 닫히고 `spring` 배율 및 빌드 표기가 갱신된다 |
| TC-09 | Draft 효과 | 다른 실행에서 `Brass Flywheel`, `Grippy Tread`를 선택한다 | 각각 회전 관성과 착지 허용각 수치가 실제 상태에 반영된다 |
| TC-10 | 착지 | 낮은 수직 속도와 노면에 가까운 각도로 착지한다 | `PERFECT MESH` 판정, 점수/Perfect 연속 기록 증가, 도면 플래시가 보인다 |
| TC-11 | 충돌/게임오버 | 큰 착지 오차 또는 프레스 충돌을 반복한다 | 리벳이 감소하고 0이 되면 결과 화면이 `BENCH FAILURE`로 열린다 |
| TC-12 | Blueprint Freeze | 결승선을 통과한다 | 청사진 결과 카드에 점수, 비행각, 최고 높이, Perfect, 빌드가 표시된다 |
| TC-13 | 재시작 | 결과 화면의 `REBUILD & RACE`를 누른다 | 점수·거리·차량 상태가 초기화되고 새 플레이가 시작된다 |
| TC-14 | localStorage | 1회 완주 후 새로고침한다 | 일일 최고점, 최고 Perfect 연속, 메달, 플레이 횟수가 복원된다 |
| TC-15 | 결정론 | 같은 날짜에 두 번 시작한다 | 트랙 번호와 지형 샘플이 동일하다 |
| TC-16 | 모바일 | 390×844 뷰포트에서 실행한다 | 가로 스크롤/브라우저 확대 없이 HUD, 게임, 양쪽 입력 구역을 조작한다 |
| TC-17 | 안전영역 | 노치 기기 에뮬레이션으로 실행한다 | 상단 HUD와 하단 입력 힌트가 `safe-area-inset` 안에 남는다 |
| TC-18 | QA 자동화 | `?qa=1`로 열고 1초 대기한다 | `window.__qaResult.pass === true`, wowImplemented 5, `pageErrors=[]` |
| TC-19 | 텍스트 건전성 | 렌더링된 본문과 `render_game_to_text()`를 검사한다 | `undefined`, `NaN` 문자열이 0개다 |
| TC-20 | 재생 제어 | `window.advanceTime(ms)`와 `window.__pistonDerby` 훅을 호출한다 | 결정론적으로 상태가 전진하며 title→play→finish/retry 경로 자동 검증이 가능하다 |
