### 1. satteri - JavaScript 생태계를 위한 고성능 Markdown 및 MDX 처리기 (2pts)
**요약**: satteri는 Rust로 파싱과 컴파일 속도를 끌어올리면서도 JavaScript 플러그인 생태계를 그대로 활용하려는 Markdown/MDX 처리기입니다. 핵심 포지션은 “JS의 플러그인 풍부함”과 “Rust의 파서 성능” 사이의 빈틈을 메우는 것입니다. README 기준으로 파싱은 Rust가 맡고, 플러그인 실행은 JS가 맡는 혼합 파이프라인 구조를 취합니다. 그래서 완전히 새 생태계를 강요하지 않으면서도 빌드 병목을 줄이려는 팀에게 매력적입니다. MDX를 많이 다루는 문서 사이트, 블로그 엔진, AI 문서 파이프라인에 바로 연결될 수 있는 성격의 도구입니다.
**기술적 배경**: JS 콘텐츠 툴링은 확장성이 좋지만 대규모 빌드에서 속도 문제가 자주 드러났고, Rust 계열은 빠르지만 기존 플러그인을 포기해야 하는 경우가 많았습니다. satteri는 이 둘을 적당히 분리해 “핵심 경로는 Rust, 사용자 확장은 JS”라는 절충안을 취한 것이 차별점입니다.
**영향 분석**: 개발자에게는 MDX 처리 성능과 기존 플러그인 자산을 동시에 지키는 선택지가 됩니다. 인디 빌더에게는 콘텐츠 파이프라인을 갈아엎지 않고도 속도를 개선할 수 있는 현실적인 중간 해법입니다.
**Master 액션 포인트**:
- eastsea.xyz 글 발행 파이프라인에서 Markdown/MDX 병목이 커지면 `전처리 Rust화 + 확장 JS 유지` 패턴을 검토할 것
- OpenClaw 스킬 문서 렌더링도 “핫패스 최적화, 확장 계층 분리” 원칙으로 재설계할 가치가 있습니다
- 원문: [bruits/satteri](https://github.com/bruits/satteri)

**Master 액션 포인트**:

GitHub와 Tokio 블로그 모두 “보일러플레이트를 줄이고 생산성을 끌어올리는 Rust 웹앱 프레임워크”라는 점을 강조합니다. 컴포넌트가 async로 DB를 직접 읽고, 별도 API 계층을 반드시 만들지 않아도 된다는 점이 특징입니다. Tokio 블로그는 특히 AI가 학습 장벽과 생산성 격차를 줄이면서 Rust의 불리함이 예전보다 작아졌다고 주장합니다. 즉 Topcoat는 프레임워크 출시이자 “AI 시대엔 Rust도 기본 선택지가 될 수 있다”는 선언에 가깝습니다.
**기술적 배경**: 프런트와 백을 모두 JS로 통일하는 흐름에 대한 Rust 진영의 반격으로 볼 수 있습니다. 서버 렌더링, HTMX에 가까운 반응성, 단일 언어 스택, AI 보조 개발이라는 네 흐름이 겹치면서 지금 타이밍에 주목받고 있습니다.
**영향 분석**: 개발자에게는 Rust 풀스택이 다시 실용적 옵션으로 보이기 시작합니다. 인디 빌더에게는 고성능 백엔드와 웹앱 개발 생산성을 동시에 노릴 수 있는 새 후보군이 하나 더 생긴 셈입니다.
**Master 액션 포인트**:
- 차기 로컬 대시보드나 운영 툴을 Rust로 묶을 필요가 생기면 Topcoat를 PoC 후보로 바로 올릴 것
- 게임 서버 운영 도구와 블로그 백오피스를 하나의 Rust 스택으로 통합할 가능성도 검토할 만합니다
- 원문: [tokio-rs/topcoat](https://github.com/tokio-rs/topcoat)
- 보강: [Announcing Topcoat](https://tokio.rs/blog/2026-07-22-announcing-topcoat)

### 15. Show GN: Skill Bridge – 여러 AI Agent의 Skill을 VS Code에서 관리하고 재사용하기 (4pts)
**요약**: Skill Bridge는 현재 워크스페이스와 중앙 스킬 라이브러리를 나란히 보여주며, 스킬을 검토·가져오기·업데이트할 수 있게 하는 VS Code 확장입니다. Marketplace 설명 기준으로 핵심은 “좋은 스킬을 재사용 자산으로 만들되, 파일 이동 전에는 사람이 확인할 체크포인트를 남긴다”는 점입니다. 변경 파일 표시, 재사용 그룹, 프리셋, NPX 라이브러리 연결 같은 실무 편의가 함께 들어 있습니다. 여러 에이전트를 동시에 쓰는 팀이 점점 많아지는 상황에서 스킬 버전 드리프트를 줄이는 데 꽤 현실적인 문제 해결책입니다. 에이전트 시대의 개발환경이 코드뿐 아니라 스킬 자산 관리까지 포함한다는 흐름을 잘 보여줍니다.
**기술적 배경**: 에이전트 활용이 늘수록 프롬프트와 스킬은 사실상 새 의존성 계층이 됩니다. 하지만 지금까지는 이 계층을 패키지처럼 다루는 도구가 부족했고, 그래서 워크스페이스별 복사와 수동 동기화가 많았습니다.
**영향 분석**: 개발자에게는 프롬프트/스킬을 재현 가능하게 운영하는 첫걸음이 됩니다. 인디 빌더에게는 “코드 저장소”와 별도로 “에이전트 작업 규칙 저장소”를 가져야 한다는 인식을 강화합니다.
**Master 액션 포인트**:
- OpenClaw 스킬도 중앙 라이브러리와 워크스페이스 차이를 시각적으로 보여주는 관리 도구가 필요합니다
- MissKim 운영 스킬은 버전·변경점·적용 범위를 패키지처럼 다루는 방향으로 빨리 정리하는 것이 맞습니다
- 원문: [Skill Bridge: AI Skill Library](https://marketplace.visualstudio.com/items?itemName=datanewbie-labs.skill-bridge-vscode)
