# D1 단일 원장 전환 계획

1. 홈페이지 종료 조건과 카테고리 API 요청을 테스트로 고정한다.
2. 표준 라이브러리만 사용하는 D1 투영 생성기를 테스트 우선으로 추가한다.
3. 배포 스테이지 생성 후 투영 생성기를 실행한다.
4. 단위·통합·전체 테스트를 실행한다.
5. 깨끗한 브랜치에 커밋하고 원격 반영 후 Worker/Pages를 배포한다.
6. 라이브 API 총계와 홈페이지 투영·사이트맵·피드 수를 대조한다.

## Red Team

- 공격: 카테고리 필터를 클라이언트에서 적용하면 해당 페이지에 일치 글이 없을 때 조기 종료한다.
  - 방어: API의 `category` 파라미터를 사용한다.
- 공격: 사이트맵 전체를 다시 만들면 도구·게임 URL이 사라질 수 있다.
  - 방어: 기존 사이트맵에서 게시물 URL만 제거하고 나머지는 보존한다.
- 공격: D1 API가 부분 페이지를 반환하면 누락된 투영이 배포될 수 있다.
  - 방어: 선언된 `total`, 고유 slug 수, 수집 수가 모두 같아야 성공한다.
- 공격: 배포 스크립트가 투영 생성 로그를 스테이지 경로로 오인할 수 있다.
  - 방어: 생성기는 정상 출력 없이 동작하고 오류만 표준 오류로 출력한다.
- 합의: 치명적 위험 없음. 실패 폐쇄 방식으로 진행한다.

✅ Anti-rationalization: 라이브 수치와 저장소 코드를 함께 확인했고 도구 출력은 총계·고유 개수로 교차 검증한다.
